01 / THE CHALLENGE

The hidden risk in everyday code changes

A tiny code edit can become a major business decision.

Rules live in code

Payment limits, positive amounts and idempotency checks are spread across C# services and SQL procedures.

Changes are hard to spot

A one-line edit can change behavior without a business-facing explanation.

Approval is disconnected

Code review and business review may happen in separate places.

POC question: Can we make a business-rule change visible before code is merged?
